# P5 Editors & In-Page Overlays Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild both editors on the plate's Technical intensity — the video editor's three-lane timeline with trim, zoom regions and export (V1–V6), the image editor's ten-tool annotation surface (I1–I4) — plus the two in-page overlays the extension injects (P1 region selection, P2 webcam).

**Architecture:** The editors are the product's only dark surfaces and the only place solid handles are permitted. The video editor keeps its existing `VideoEditorContext` but its timeline is rewritten to three named lanes (clip, zoom, audio) with two editing verbs in the transport bar; everything else appears only on selection. The image editor's toolbar becomes ten tools with single-key shortcuts driven by one keymap. Both editors share a keyboard-shortcut registry so a shortcut cannot be bound twice.

**Tech Stack:** React 19, Fabric.js (image editor), the existing `VideoEditorContext`, `@snaprec/design-system` dark tokens, plain JS for the extension overlays.

## Global Constraints

Inherited verbatim from `2026-08-08-plate-redesign-roadmap.md` § "Global constraints". Every task's requirements implicitly include that section.

Additional, P5-specific:

- **The editors are Technical workspaces and get explicit dark tokens** — `--sr-surface-carbon`, `--sr-surface-well`, `--sr-surface-panel-dark`. Not a `dark:` variant.
- **This is the only surface where solid cyan handles are correct**, and only on the timeline's trim points. The preview above keeps registration marks.
- **Three lanes, not twelve tracks:** clip, zoom, audio. Split and Add zoom are the only two editing verbs in the transport bar.
- **Progressive complexity:** speed, lane visibility and per-region settings appear only when something is selected.
- **Every icon-only control has a tooltip naming its shortcut.**
- **Trimmed heads are dimmed to 60%, never removed** — what you cut stays visible and recoverable.
- **`fab.css` and `content.css` are injected into arbitrary pages** and cannot read `--sr-*`. Hex literals are correct there and only there, each with a comment naming the token it mirrors.

Create `apps/web/src/lib/shortcuts.ts`:

```ts
/** One registry per scope so a shortcut cannot be silently bound twice.
 *
 * The editors have 20+ bindings between them and the prototype requires that
 * every icon-only control name its shortcut in a tooltip. Both facts argue for
 * a single table rather than scattered keydown handlers. */

export interface Binding {
  /** 'S', 'mod+z', 'mod+shift+z'. `mod` is ⌘ on Apple, Ctrl elsewhere. */
  key: string;
  label: string;
  description: string;
  scope: 'video' | 'image' | 'global';
}

export interface Registry {
  bindings: Binding[];
  find(label: string): Binding | undefined;
  handle(e: KeyboardEvent, run: (binding: Binding) => void): void;
}

export function createRegistry(bindings: Binding[]): Registry {
  const seen = new Set<string>();
  for (const b of bindings) {
    const id = `${b.key.toLowerCase()} (${b.scope})`;
    if (seen.has(id)) throw new Error(`duplicate binding: ${id}`);
    seen.add(id);
  }

  return {
    bindings,
    find: (label) => bindings.find(b => b.label === label),
    handle(e, run) {
      const t = e.target as HTMLElement | null;
      if (t && (t.tagName === 'INPUT' || t.tagName === 'TEXTAREA' || t.isContentEditable)) return;
      const hit = bindings.find(b => matches(b, e));
      if (hit) { e.preventDefault(); run(hit); }
    },
  };
}

const parse = (key: string) => {
  const parts = key.toLowerCase().split('+');
  return {
    mod: parts.includes('mod'),
    shift: parts.includes('shift'),
    alt: parts.includes('alt'),
    base: parts.at(-1)!,
  };
};

export function matches(binding: Binding, e: KeyboardEvent): boolean {
  const p = parse(binding.key);
  const mod = e.metaKey || e.ctrlKey;
  return e.key.toLowerCase() === p.base
    && mod === p.mod
    && e.shiftKey === p.shift
    && e.altKey === p.alt;
}

const isApple = () => typeof navigator !== 'undefined' && /Mac|iPhone|iPad/.test(navigator.platform);

function pretty(key: string): string {
  const p = parse(key);
  return [
    p.mod ? (isApple() ? '⌘' : 'Ctrl') : '',
    p.shift ? '⇧' : '',
    p.alt ? '⌥' : '',
    p.base.length === 1 ? p.base.toUpperCase() : p.base,
  ].join('');
}

/** Every icon-only control gets one of these. */
export function tooltipFor(label: string, binding: Binding | undefined): string {
  return binding ? `${label} — ${pretty(binding.key)}` : label;
}
```

> `navigator.platform` is deprecated. It is still the most reliable Apple check
> in practice, and the fallback is only cosmetic (`Ctrl` vs `⌘`). If it is
> removed, switch to `navigator.userAgentData?.platform`.
